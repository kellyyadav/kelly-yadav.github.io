GeoTrust Navigator

Trust-scored GPS tracking with spoofing and outlier detection

GPS readings from phones are noisy, and location can be spoofed. GeoTrust ingests raw GPS streams, smooths them with a Kalman filter, flags suspicious points, and assigns every point a 0–100 trust score, so downstream systems know how much to believe each position.

What I built
  • Spring Boot REST API that ingests GPS point streams and persists results
  • Kalman filter that smooths noisy coordinates into a corrected track
  • Outlier and spoofing detection for implausible jumps relative to the predicted track
  • Per-point trust score (0–100) combining filter residuals and detection flags
  • Simulator that generates a noisy walk plus a spoofed jump and reports RMSE for raw vs corrected positions
  • Leaflet dashboard: red = raw, green = corrected, orange = flagged points

Why a Kalman filter instead of a moving average?

GPS noise is not uniform. A Kalman filter keeps a running estimate of position and velocity and weighs each new reading by its uncertainty, so it tracks real movement while damping jitter. A moving average lags on turns and blurs real motion.

  • Predict the next state from the last one
  • Update the estimate using the new reading, weighted by uncertainty
  • Compare the reading to the prediction to detect implausible jumps

Why realtime subscriptions instead of polling?

Battles need sub-second updates for both players. Subscribing to Postgres changes pushes updates when rows change, which avoids constant polling and keeps load on the database predictable.

  • Leaderboards and battle status update on change events
  • Question generation stays behind a serverless route, not in the browser
  • Row-level data stays in one source of truth (Postgres)
Trade-off I'm aware of: CaloriQ currently calls the Anthropic API from the frontend, which exposes the key to users. The production fix is to move that call behind a serverless function, the same pattern CodeArena uses. I'm planning that migration.
