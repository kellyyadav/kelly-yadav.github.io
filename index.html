GeoTrust Navigator

GPS correction and spoof detection platform with a 0–100 trust score per point

Phone GPS readings are noisy, and location can be spoofed. GeoTrust ingests raw coordinates over REST, returns a Kalman-filtered estimate for each device, flags impossible speeds and sudden jumps, and scores every point so downstream systems know how much to trust it.

What I built
  • Spring Boot REST APIs that ingest GPS coordinates and return corrected location estimates
  • Per-device Kalman filter, with filter state kept separate for each device
  • Anomaly detection for impossible speeds and sudden location jumps
  • 0–100 trust score for every point, based on filter residuals and detection flags
  • PostgreSQL on Supabase for storage, with the backend containerised in Docker
  • Unit tests run automatically through GitHub Actions on every change
  • Leaflet dashboard comparing raw and corrected routes, with flagged points highlighted

Why a Kalman filter instead of a moving average?

GPS noise is not uniform. A Kalman filter keeps a running estimate of position and velocity and weighs each new reading by its uncertainty, so it tracks real movement while damping jitter. A moving average lags on turns and blurs real motion.

  • Predict the next state from the last one
  • Update the estimate with the new reading, weighted by uncertainty
  • Compare the reading to the prediction to detect implausible jumps

Why WebSockets for battles?

Both players need to see the battle state change without refreshing. A persistent WebSocket connection pushes updates in both directions, which suits a live 1v1 better than repeatedly polling the server.

  • Matchmaking and battle status are pushed to both clients
  • Question generation stays behind a serverless route, not in the browser
  • Postgres stays the single source of truth for profiles, questions, and solves
Trade-off I'm aware of: CaloriQ's current setup exposes the AI key on the frontend, which is a risk for a public deployment. The fix is to move AI calls behind a serverless function, the same pattern CodeArena uses. That migration is the next thing I'm planning for CaloriQ.
